# M4 提示与答案（重点）：WebView 容器

格式同 `hints/M2.md`：提示 1 在代码注释里，提示 2 和答案折叠在下面。展开过答案的，在 `notes/android-M4.md` 记一笔。M4 是项目目标本身，不许跳，时间盒 12h（8h × 1.5）。

**离线包拦截（M4-1 ~ M4-4）已经写好**，对应 spec M4 的「离线包 case（基线）」：一进 H5 页就能看到「离线包测试页」，`location` 是 `https://h5.offline.test/index.html`。这 4 个空不用做，读懂代码和下面的讲解即可，想一想照样值得做。bridge、白屏的空没填时，页面上 `getDeviceInfo` 显示 `TIMEOUT` 失败是正常的。

### 直达入口（不经过列表页）

```sh
adb shell am start -S -n com.example.mobile3end/.MainActivity --es m3e.h5 normal
```

带了 `m3e.h5` 这个 extra，`MainActivity` 只显示 H5 页：不渲染列表页、不需要 `STAGE ≥ 4`、不碰 M1–M3 的空。值是 `H5Case` 的 key，换成 `blank` / `missing` / `slow` / `foreign` / `load-error` / `render-crash` 就直接打开对应用例。`-S` 是先把正在跑的 App 停掉再启动，保证进的是新的 Activity。页面左上「← 返回」关掉这个 Activity。M3 还没做完时先用它进 H5 页，不用改 `STAGE`。

## 开始前

- 用上面的直达入口就能先开始；走正常入口要把 `Stage.kt` 里的 `STAGE` 改成 `4`。列表页右上角出现「H5」按钮；H5 页右上角「用例」菜单切换 `?case=`，顶部状态条显示 `OFFLINE_404` 次数和白屏检测结果

## 整体结构

逻辑和胶水分开，逻辑都有 JVM 单测，胶水有模拟器上的仪器测试（真的加载离线包、真的走 bridge）：

|---|---|---|
| `web/OfflinePackage.kt` | URL → (状态码, MIME, 数据)，纯逻辑 | M4-1、M4-2、M4-3（已写好，读懂即可） |

建议顺序：读 M4-1 → M4-4（已写好，页面已经能显示）→ M4-5 → M4-6（bridge 通了）→ M4-7 → M4-8 → M4-9 → M4-10 → M4-11 → 手工任务。

一进 H5 页就会执行到的空：
- M4-1 ~ M4-4（已写好）：注入 bridge 前判 origin、拦截 `index.html` / `app.js` / `style.css` / `favicon.ico`
- M4-6 → M4-5：`app.js` 挂载完立刻调 `getDeviceInfo`。没填时页面照常渲染，`getDeviceInfo` 3s 后显示 `TIMEOUT`
- M4-8：`onPageFinished` 里的白屏检测。没填时不检测，状态条「白屏检测：—」
- M4-7：切前后台时（STAGE ≥ 3 才有前后台事件）

这些回调里碰到 TODO 不会崩，是 `TodoGuard` 做的：WebView 的回调里碰到 TODO 时先接住、记下来（logcat 里一行 `An operation is not implemented: M4-x（还没填，先返回默认值）`），测试等待超时时再报出来，不然整个 App（连同测试进程）会直接崩。所以不用开关，bridge / 白屏填没填，页面都能打开。

`./check.sh M4` 开着模拟器约 2 分钟。现在 `m4_0_` 示例和 M4-1 ~ M4-4 的测试是 ✅；依赖 bridge 的仪器测试要等 M4-5、M4-6 填完才陆续变绿，之前会显示「运行到了未填的 M4-x」。JVM 单测不受影响，先盯着它们做。

调 H5 时同时开着 logcat（过滤 `tag:M3E`）和 `chrome://inspect`（手工任务 2），一个看原生日志，一个看 H5 的 Console / Network。

## M4-5 bridge 分发 · `web/Bridge.kt`（完整方法）

<details><summary>提示 2</summary>

顺序很重要：
1. `pageUrl == null || !isOfflineOrigin(pageUrl)` → 打日志 `[BRIDGE] 忽略来自 $pageUrl 的消息`，返回 null。**先校验来源，再碰消息内容**
2. `parseJsonObject(raw)`，再 `.string("id")`，有一个是 null → 打日志，返回 null
3. `message.string("method")`；`message["params"] as? JsonObject ?: JsonObject(emptyMap())`
4. `when (method)`：`"getDeviceInfo"` → `BridgeJs.ok(id, deviceInfo().toJson())`；`"toast"` → `toast(params.string("text").orEmpty())` 然后 `BridgeJs.ok(id, JsonObject(emptyMap()))`；`else` → `BridgeJs.error(id, ERR_METHOD_NOT_FOUND, "method $method not found")`
</details>

<details><summary>答案</summary>

```kotlin
if (pageUrl == null || !isOfflineOrigin(pageUrl)) {
    log("[BRIDGE] 忽略来自 $pageUrl 的消息")
    return null
}
val message = parseJsonObject(raw)
val id = message?.string("id")
if (message == null || id == null) {
    log("[BRIDGE] 消息格式不对：$raw")
    return null
}
val method = message.string("method")
val params = message["params"] as? JsonObject ?: JsonObject(emptyMap())
log("[BRIDGE] ← $method id=$id")
return when (method) {
    "getDeviceInfo" -> BridgeJs.ok(id, deviceInfo().toJson())
    "toast" -> {
        toast(params.string("text").orEmpty())
        BridgeJs.ok(id, JsonObject(emptyMap()))
    }
    else -> BridgeJs.error(id, ERR_METHOD_NOT_FOUND, "method $method not found")
}
```
</details>

想一想：
- 为什么用 `JsonObject` 而不是 M2 那样的 `@Serializable data class`？（`params` 每个方法都不一样）真实容器里方法有几百个，`when` 会变成什么？（注册表：`Map<String, Handler>`）
- 🔬 用 K1-11 的 `toJs` 手拼字符串，`m4_5_outputIsEscaped` 会挂。H5 传来的 id 里有个 `"`，生成的 JS 长什么样？如果是 toast 文案、文件名呢？（这就是 XSS 进 Native 的路）
- 不可信来源直接 `return null`，H5 会等到 3s 超时。为什么不回一个 `ok: false`？
- 返回值是「要执行的 JS 字符串」，而不是直接调 `evaluateJavascript`。这样拆的好处是什么？（看测试是怎么写的；鸿蒙 M4-5 是同样的拆法）

## M4-8 白屏检测主流程 · `web/WhiteScreen.kt`（完整方法）

<details><summary>提示 2</summary>

```kotlin
val myRound = round
fun check(elapsed: Long) {
    // 1. round 变了就 return（等待期间开始了新页面）
    // 2. host.evaluate(ROOT_CHILD_COUNT_JS) { result -> ... }
    // 3. 回调里 round 也可能变了，再判一次
    // 4. when (policy(elapsed, parseChildCount(result))) { OK -> {}; WHITE -> report(...); RETRY -> host.schedule(...) { check(elapsed + CHECK_DELAY_MS) } }
}
host.schedule(CHECK_DELAY_MS) { check(CHECK_DELAY_MS) }
```

Kotlin 允许在函数里定义局部函数，局部函数可以递归。上报用私有的 `report(...)`（它负责「同一轮只报一次」），不要直接调 `host.report`。
</details>

<details><summary>答案</summary>

```kotlin
val myRound = round
fun check(elapsed: Long) {
    if (myRound != round) return
    host.evaluate(ROOT_CHILD_COUNT_JS) { result ->
        if (myRound != round) return@evaluate
        when (policy(elapsed, parseChildCount(result))) {
            CheckDecision.OK -> {}
            CheckDecision.WHITE -> report(WhiteReason.EMPTY_ROOT, url)
            CheckDecision.RETRY -> host.schedule(CHECK_DELAY_MS) { check(elapsed + CHECK_DELAY_MS) }
        }
    }
}
host.schedule(CHECK_DELAY_MS) { check(CHECK_DELAY_MS) }
```
</details>

想一想：
