## M2-1 解析 JSON · `data/FilesJson.kt`

<details><summary>提示 2</summary>

`decodeFromString` 拿到的是 `FilesResponse`，里面是 `List<FileDto>`，再 `.map { }` 成 `FileItem`。
type 的转换不能用 `FileType.valueOf(...)`：遇到不认识的值它会抛异常，一条脏数据就让整个列表都显示不出来。用 `FileType.entries.firstOrNull { ... } ?: FileType.DOC`。
</details>

<details><summary>答案</summary>

```kotlin
return AppJson.decodeFromString<FilesResponse>(json).files.map { dto ->
    val type = FileType.entries.firstOrNull { it.name.equals(dto.type, ignoreCase = true) } ?: FileType.DOC
    FileItem(dto.id, dto.name, type, dto.size, dto.mtime)
}
```
</details>

想一想：
- 把 `AppJson` 换成默认的 `Json`，哪个测试会挂？为什么接口「多给字段」在客户端是常态？（新版服务端 + 老版 App）
- 对工作：H5 通过 JSBridge 收到 Native 回传的 JSON，Native 那边如果也这样严格解析 H5 传的参数，H5 多传一个字段会怎样？

## M2-7 先缓存后网络 · `data/FileListLoader.kt`（函数体）

<details><summary>提示 2</summary>

分两段：
1. 读缓存，决定先显示什么：有缓存 → `Loaded(cached)`；没缓存且当前不是 Loaded → `Loading`
2. `try` 请求网络：成功 → 写缓存、`Loaded(fresh)`；`CancellationException` 原样抛；其他异常 → 当前是 Loaded 就只打日志，否则 `Failed(messageOf(e))`
</details>

<details><summary>答案</summary>

```kotlin
val cached = readCache()
if (cached != null) {
    _state.value = ListUiState.Loaded(cached)
} else if (_state.value !is ListUiState.Loaded) {
    _state.value = ListUiState.Loading
}
try {
    val fresh = remote.fetch()
    writeCache(fresh)
    _state.value = ListUiState.Loaded(fresh)
} catch (e: CancellationException) {
    throw e
} catch (e: Exception) {
    if (_state.value is ListUiState.Loaded) {
        log("刷新失败，继续显示已有数据：$e")
    } else {
        _state.value = ListUiState.Failed(messageOf(e))
    }
}
```
</details>

想一想：
- 为什么 `catch (e: Exception)` 会吃掉取消？吃掉以后会出什么 bug？（测试 `m2_7_cancelIsNotFailure`）
- 网络失败时用户看到的是旧缓存，但不知道它是旧的。要不要提示？线上 App 是怎么做的？
- 对工作：线上 App 的离线包也是「先用本地包，再后台检查更新」。新包下载好之后是立刻替换当前页面，还是下次打开才生效？各自会出什么问题？

## M2-9 手工任务：网络权限 · `AndroidManifest.xml`

不是 TODO，`check.sh` 的「未填的空」不会列它，Manifest 里留了一行注释指位置。M2-10 同理。

<details><summary>提示 2</summary>

`<manifest>` 下、`<application>` 之前，声明一个 `uses-permission`。INTERNET 是普通权限，声明就有，不用运行时申请。
</details>

<details><summary>答案</summary>

```xml
<uses-permission android:name="android.permission.INTERNET" />
```
</details>

想一想：
- 🔬 出题时发现：**不写这行，App 照样能联网，`m2_9` 也照样通过**。原因是 OkHttp 5 的 Android 包自带一份 Manifest，里面声明了 INTERNET，构建时被合并进来了。自己验证：Android Studio 打开 `AndroidManifest.xml`，底部切到 Merged Manifest 标签，看 INTERNET 那行来自谁；或者看 `app/build/outputs/logs/manifest-merger-debug-report.txt`
- 那为什么还要自己写？（提示：哪天换掉 OkHttp，或者只用 WebView 不用 OkHttp）
- 对工作：线上 App 最终的权限，是自己声明的 + 所有 SDK 带进来的。隐私合规审查看的是 merged manifest，不是源码里那份

## M2-10 手工任务：只对 mock 地址放行明文 · `AndroidManifest.xml` + `res/xml/network_security_config.xml`

<details><summary>提示 2</summary>

targetSdk ≥ 28 默认禁止明文 http。最省事的 `android:usesCleartextTraffic="true"` 是全局放开，测试 `m2_10` 会拒绝它。正确做法：在 `res/xml/` 下写一份 network security config，用 `<domain-config cleartextTrafficPermitted="true">` 只列 `10.0.2.2`，再在 `<application>` 上用 `android:networkSecurityConfig` 引用它。
</details>

<details><summary>答案</summary>

`res/xml/network_security_config.xml`：

```xml
<?xml version="1.0" encoding="utf-8"?>
<network-security-config>
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="false">10.0.2.2</domain>
    </domain-config>
</network-security-config>
```

`AndroidManifest.xml` 的 `<application>` 上：

```xml
android:networkSecurityConfig="@xml/network_security_config"
```
</details>

想一想：
- 🔬 没放行时失败态显示什么？异常信息里有 `CLEARTEXT` 字样吗？
- 真机调试要访问 Mac 的局域网 IP，这份配置要怎么改？能不能写成网段？
- 对工作：这份配置**也管 WebView**。线上 App 的 H5 页面里如果有 http 的图片 / 接口，在 Android 上会被拦，在 iOS 上受 ATS 管。排查「某张图在 Android 上不显示」时，先看 logcat 里有没有 cleartext 相关的报错
