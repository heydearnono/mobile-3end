## K1-1 when 表达式 · `Expressions.kt`

<details><summary>提示 2</summary>

`when` 不带参数时，每个分支左边是一个 Boolean 条件，从上往下第一个为 true 的分支生效，相当于 if / else if 链。`0` 和 `0L` 的区别：`bytes` 是 Long，比较时写 `0L`（写 `0` 会报类型不匹配）。
</details>

<details><summary>答案</summary>

```kotlin
fun sizeLabel(bytes: Long): String =
    when {
        bytes == 0L -> "—"
        bytes < 1024 -> "$bytes B"
        else -> formatSize(bytes)
    }
```
</details>

想一想：把 `else` 分支删掉会怎样？为什么 M2-8 的 `when (state)` 不写 else 也能编译，这里不行？

## K1-2 try 是表达式 · `Expressions.kt`

<details><summary>提示 2</summary>

`try { A } catch (...) { B }` 整体的值：没抛异常就是 A 的最后一个表达式，抛了就是 B 的最后一个表达式。前面加 `return` 就把这个值返回出去。
</details>

<details><summary>答案</summary>

```kotlin
return try {
    parseFiles(json)
} catch (e: SerializationException) {
    null
}
```
</details>

想一想：
- 这个函数写成表达式函数体（`= try { ... } catch ...`）也行，试一下
- 对比你在 M2-4 写的 `runCatching { }.onFailure { }.getOrNull()`：`runCatching` 也是一个普通的高阶函数，⌘ 点进去看它里面就是 try / catch

## K1-3 lambda 的返回值 · `Expressions.kt`

<details><summary>提示 2</summary>

lambda 里可以写多行，最后一行的值就是返回值。在这里写 `return "..."` 会报错：lambda 里的裸 `return` 指的是「从外层函数返回」，而这个 lambda 外面没有函数。
</details>

<details><summary>答案</summary>

```kotlin
val describe: (FileItem) -> String = { file ->
    val icon = iconOf(file.type)
    "$icon ${file.name}"
}
```
</details>

想一想：
- `(FileItem) -> String` 是函数类型，≈ TS 的 `(file: FileItem) => string`。测试里的 `listOf(doc, image).map(describe)` 把它当参数传，和 TS 的 `arr.map(describe)` 一样
- 回到 M2-2：`client.newCall(request).execute().use { response -> ... parseFiles(...) }`，`use` 的 lambda 最后一行是 `parseFiles(...)`，所以 `use { }` 整体的值就是列表；你当时缺的是外层块函数体的 `return`

## K1-4 ?. 和 ?: · `NullSafety.kt`

<details><summary>提示 2</summary>

`file?.name` 的类型是 `String?`，再接 `?: "文件不存在"` 就变回 `String`。
</details>

<details><summary>答案</summary>

```kotlin
fun displayName(file: FileItem?): String =
    file?.name ?: "文件不存在"
```
</details>

想一想：去掉 `?:` 部分，编译器报什么错？这就是 Kotlin 比 TS 严的地方：TS 关掉 `strictNullChecks` 就不管了，Kotlin 没有这个开关。

## K1-5 ?. 链 · `NullSafety.kt`

<details><summary>提示 2</summary>

`firstOrNull { }` 找不到时返回 null，所以它后面也要接 `?.`。每一步 `?.` 遇到 null 都会让整条链直接变成 null，最后 `?: 0` 兜底。
</details>

<details><summary>答案</summary>

```kotlin
fun firstImageSize(files: List<FileItem>?): Long =
    files?.firstOrNull { it.type == FileType.IMAGE }?.size ?: 0
```
</details>

想一想：`it` 是什么？lambda 只有一个参数时可以不起名字，默认叫 `it`。什么时候应该显式写 `{ file -> ... }`？（提示：嵌套 lambda 时两个 `it` 会混）

## K1-6 smart cast / as? · `NullSafety.kt`

<details><summary>提示 2</summary>

```kotlin
if (state is ListUiState.Failed) state.message else null
```
`is` 判断之后，`state` 在这个分支里自动被当成 `Failed`，可以直接 `.message`。另一种写法 `as?` 一行就够。
</details>

<details><summary>答案</summary>

```kotlin
fun failedMessage(state: ListUiState): String? =
    (state as? ListUiState.Failed)?.message
```
</details>

想一想：`as`（不带问号）转不了会怎样？`App.kt` 里 `(state as? ListUiState.Loaded)?.files` 用的就是这个写法，现在能读懂了吗？

## K1-7 写一个高阶函数 · `ScopeFunctions.kt`

<details><summary>提示 2</summary>

`block: () -> T` 是一个参数，类型是「无参、返回 T 的函数」，调用就是 `block()`。`finally` 不管有没有异常都会执行；`try` 里的 `return` 会先跑完 `finally` 再真正返回。
</details>

<details><summary>答案</summary>

```kotlin
logs += "start $name"
try {
    return block()
} finally {
    logs += "end $name"
}
```
</details>

想一想：
- `<T>` 是泛型，和 TS 的 `function withLog<T>(...)` 一样。调用 `withLog(logs, "x") { 42 }` 时 T 被推断成了什么？
- 你刚写的 `withLog` 和 `withContext(io) { ... }`、`use { ... }` 是同一种东西。⌘ 点开 `use`，对比一下它和你的实现

## K1-8 带接收者的 lambda · `ScopeFunctions.kt`

<details><summary>提示 2</summary>

`buildString { }` 里的 `this` 是一个 `StringBuilder`，所以 `appendLine(...)` 等于 `this.appendLine(...)`。lambda 结束后 `buildString` 返回拼好的字符串。
</details>

<details><summary>答案</summary>

```kotlin
fun summary(files: List<FileItem>): String =
    buildString {
        files.forEach { file -> appendLine("${iconOf(file.type)} ${file.name}") }
    }
```
</details>

想一想：
- 这个也能写成 `files.joinToString("") { ... + "\n" }`。什么时候用 `buildString` 更合适？
- Compose 的 `Column { Text("a") }`、`Scaffold(topBar = { ... }) { ... }` 是同一种写法：组件就是函数，`{ }` 是传进去的 lambda。M1 的 `Screens.kt` 回头再看一遍

## K1-9 ?.let · `ScopeFunctions.kt`

<details><summary>提示 2</summary>

`toLongOrNull()` 转不了返回 null，接 `?.let { it * 1000 }`：非空时把值交给 lambda，lambda 的结果就是整个表达式的值；是 null 就整条链得 null。
</details>

<details><summary>答案</summary>

```kotlin
fun parseMtimeMs(raw: String?): Long? =
    raw?.toLongOrNull()?.let { it * 1000 }
```
</details>

想一想：`let`、`also`、`apply` 的区别只有两点：lambda 里用 `it` 还是 `this`，返回 lambda 的结果还是对象本身。把这三个各自适合的场景写进速查表

## K1-11 sealed + when · `Types.kt`

<details><summary>提示 2</summary>

```kotlin
val body = when (result) {
    is BridgeResult.Ok -> "..."
    is BridgeResult.Err -> "..."
}
return "window.__bridgeCallback($body)"
```
字符串里的双引号写成 `\"`；取属性要用 `${result.code}`，只有简单变量名才能写 `$id`。也可以用 `"""` 原始字符串，里面的 `"` 不用转义。
</details>

<details><summary>答案</summary>

```kotlin
val body = when (result) {
    is BridgeResult.Ok -> "{\"id\":\"$id\",\"ok\":true,\"data\":${result.dataJson}}"
    is BridgeResult.Err ->
        "{\"id\":\"$id\",\"ok\":false,\"error\":{\"code\":\"${result.code}\",\"message\":\"${result.message}\"}}"
}
return "window.__bridgeCallback($body)"
```
</details>

想一想：
- 给 `BridgeResult` 加第三种 `data object Pending : BridgeResult`，看编译器在哪报错
- 对工作：这就是 M4 里 Native 回调 H5 的样子。`message` 里如果有 `"` 或换行，拼出来的 JS 会怎样？真实容器是怎么做转义的？M4 再回答

## K1-14 并发 · `Coroutines.kt`

<details><summary>提示 2</summary>

直接写 `first() + second()` 是顺序执行，总共 2 秒。`async { }` 立刻启动一个子协程并返回 `Deferred`（≈ Promise），之后 `await()` 拿结果。`async` 必须在一个协程作用域里调，`coroutineScope { }` 就是创建这个作用域。
</details>

<details><summary>答案</summary>

```kotlin
coroutineScope {
    val a = async { first() }
    val b = async { second() }
    a.await() + b.await()
}
```
</details>

想一想：
- TS 里 `const a = fetchA(); const b = fetchB(); await a; await b` 是并发的，因为 Promise 创建时就开始执行。Kotlin 里 `val a = first()` 就会挂起等它完成。这是 TS 程序员写 Kotlin 最容易踩的坑
- 两个里有一个抛异常，另一个会怎样？（结构化并发：兄弟协程一起取消。对比 `Promise.all` 的行为）

## K1-15 超时 · `Coroutines.kt`

<details><summary>提示 2</summary>

`withTimeoutOrNull(毫秒) { ... }`：时间内完成返回结果，超时就取消 block 并返回 null。
</details>

<details><summary>答案</summary>

```kotlin
suspend fun <T> fetchOrNull(timeoutMs: Long, block: suspend () -> T): T? =
    withTimeoutOrNull(timeoutMs) { block() }
```
</details>
