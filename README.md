# 三端（Android / iOS / 鸿蒙）学习项目

## 目标

作为 FE 看懂移动 App 的 H5 容器：WebView、JSBridge、离线包、白屏检测。排查容器问题时能看懂原生侧在做什么，和客户端同学说同一种语言。

**不是**要成为原生开发。和容器无关的原生知识（动画、复杂布局、性能调优等）只学到够用为止。

## 做法

一份 `spec.md`，三端各实现一遍。纵向一端打穿再移植，顺序固定：

1. **Android** —— 份额最大、机型最碎，容器问题最多
2. **iOS** —— 拦截机制和另外两端差异最大，放第二个对比最明显
3. **鸿蒙** —— ArkTS ≈ TS，对 FE 最好上手，放最后成本最低

每个里程碑结束做两件事：更新 `compare.md` 对应行，写一份 `notes/<端>-M<n>.md`。

## 填空

代码里留了 `TODO("M1-3")` 这样的空位：工程能编译，跑到这一行才抛异常。

```sh
cd android
./check.sh M1     # 列出未填的空，跑测试，逐空显示 ✅ / ❌
```

- 需要模拟器的 UI 测试，没开模拟器时只跑 JVM 单测
- 提示分三级：代码注释 → `hints/M<n>.md` 的提示 2 → 答案（折叠）。看过答案在 notes 记一笔
- 空逐步变大：M1 补一行 → M2–M3 补函数体 → M4 关键判断 + 一个完整方法 → M5 不留空 → iOS / 鸿蒙以 Android 版为参考自己迁移

## 时间盒

单位：小时 / 端。第一个端（Android）按 1.5 倍算。

| 里程碑 | 内容 | 时间盒 |
|---|---|---|
| M0 | 环境、真机、日志 | 2h |
| M1 | UI、状态、路由 | 4h |
| M2 | 网络、存储 | 4h |
| M3 | 生命周期、线程 | 3h |
| **M4** | **WebView 容器** | **8h** |
| M5 | 打包、异常采集 | 3h |

合计约 24h / 端，三端约 85h。

超时就停：把卡点写进 notes，跳到下一个里程碑。**M4 例外**，M4 是目标本身，不许跳。

## 结束标准

M4 三端都完成后，对照一个真实 App 的三端容器代码（自己工作中的或开源的），只读 WebView 初始化、离线包拦截、JSBridge、白屏检测这四块，产出 `notes/real-code.md`（真实实现和我的实现差在哪、为什么那么做）。写完这份，项目结束。

```

```

## 本地 mock 服务

在仓库根目录执行：

```sh
python3 -m http.server 8000 -d mock
```

各端访问宿主机的地址：

| 环境 | 地址 |
|---|---|
| Android 模拟器 | `http://10.0.2.2:8000` |
| iOS 模拟器 | `http://localhost:8000` |
| 鸿蒙模拟器 | 待实测，结果记到 `notes/harmony-M2.md` |
| 真机 | Mac 的局域网 IP，手机和 Mac 在同一 Wi-Fi |

## 工具

Android Studio、Xcode、DevEco Studio。实际使用的版本记到各端的 `notes/<端>-M0.md`。
